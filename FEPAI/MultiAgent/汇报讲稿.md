# 汇报讲稿

## 开场

老师同学们好，我是今天第三个汇报的小组，我是汇报人黄嘉诚，我们组的论文选题是基于角色分工的多智能体大模型系统对编程任务性能的影响。

接下来我将从选题背景、研究方法、实验数据分析以及结论与启示四个方面进行汇报。

## 选题背景

首先，我介绍一下本研究的选题背景。

最近几年，大语言模型的快速发展在虚拟世界乃至现实世界中引发了广泛的关注，它在语言理解、代码生成方面展现出的强大能力令人印象深刻。但是，当大语言模型被应用于复杂度较高的编程任务，比如说实际软件工程场景中的后端管理系统开发时，它的表现不尽人意，常常出现 API 调用错误、代码结构与项目组织方式不一致等问题。

针对上述现象，研究者和开发者逐渐认识到，大语言模型具备较强的上下文理解能力，如果能够引入代码仓库、目录结构等运行环境信息，并进一步赋予其与环境交互的能力，可能有助于提升其在复杂软件开发任务中的表现。在这一背景下，Agent这种任务执行范式逐渐受到关注。

Agent通常被翻译为“智能体”，指能够自主感知环境、进行规划并执行决策的计算实体。以大语言模型作为核心构建 Agent，使其具备更强的语义理解与推理能力，从而能够以更高程度的自动化和更高水准完成相对复杂的编程任务。

但在实际应用中，单一 Agent 在面对高复杂度或高负载任务时仍然存在一定局限性，例如可能产生未充分检查的结果，或表现出过度自信的输出行为。因此，由多个Agent通过角色分工协作组成的多智能体系统被提出，且成为了现在的研究热点之一。

本研究关注在不同难度的编程任务中，单智能体与基于角色分工的多智能体系统在任务性能上的差异，比如说在什么情境下单Agent与多Agent会出现明显的性能差异，又在什么情况下近似；并通过系统性的对比实验，对多智能体系统在编程任务中的整体效果进行分析。

## 研究方法

这张图展示的是整个实验的总体设计。



我构建了一组编程任务，共有七个，涵盖不同类型与难度，用作所有实验对象的统一输入。

在实验对象的选择上，我对比了三类系统：纯大模型、具备规划与自检能力的单智能体系统，以及基于角色分工的多智能体系统。所有系统使用相同的Gemini3pro模型，并在统一的实验流程下处理相同的任务，以保证对比的公平性。

在实现对象完成任务的开发后，我采用基于用例的评估方式，对每个任务的输出结果进行人工验收。每个任务对应一组预先定义的用例，从用户视角评估系统是否满足预期行为，而不依赖具体实现细节。

最后，我会基于该评估结果对系统的性能表现进行汇总与分析，从而研究多Agent系统对编程任务性能的影响。



接下来对一些细节做些补充。

首先是编程任务部分，我定下了七个编程任务，两个简单、三个中等、两个困难，这些任务我存在了一个json文件里方便自动化读取之类的操作，图中是两个例子，篇幅限制没有展示InputPrompt和UseCase。

接下来是实验过程，同时对三类实验对象的结构做一个统一说明。

第一类实验对象是纯大模型，也就是直接通过网页版的大模型API接收用户输入的prompt，并以one-shot的方式生成最终代码结果。这一系统不包含显式的规划、记忆或自检过程，作为基线方法，用于刻画大模型在最基础使用方式下的性能表现。

第二类实验对象是单智能体系统。与纯大模型不同，单智能体系统在内部引入了一个基于大模型的控制器，控制器利用内部记忆进行状态维护，以LLM为核心进行决策。在任务过程中，智能体可以通过sensor感知环境信息，并通过actuator执行操作。

第三类实验对象是基于角色分工的多智能体系统，也是本文关注的核心实验组。如图右上方所示，该系统由多个功能明确的智能体组成，分别承担规划、编程和审查等不同职责。具体来说，Planner负责对任务进行拆解并明确需求，Programmer负责根据规划完成代码实现，而Reviewer则对生成结果进行检查，并提出修改建议。多个智能体通过有限轮次的协作完成同一编程任务。

这三类系统均接收完全相同的任务prompt，并遵循统一的输出格式要求，只会在system prompt有些差异。所有系统生成的最终代码都会进入同一评估阶段。

最后是评估部分，在评估的时候会对软件进行用例测试，在特定情形下得到的输出符合逻辑、要求且没有异常就得到满分两分，部分正确就是一分，完全不对就是0分。
